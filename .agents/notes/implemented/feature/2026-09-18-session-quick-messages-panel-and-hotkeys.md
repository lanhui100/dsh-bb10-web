# Agent Note: session-quick-messages-panel-and-hotkeys

Status: implemented

## Problem

在 BlackBerry Q20 移动端（720x720 物理小方屏）输入场景中，使用全键盘逐字输入常用 prompt（如“继续执行”、“优化当前代码”、“解释上述内容”、“列出后续待办”等）效率受限。用户需要在会话详情界面通过快捷键直接呼出快捷消息面板，用 `J`/`K`/触控板快速挑选、按 `Enter` 立即发送该消息，并且面板内支持通过按钮或按 `A` 键快速新增快捷消息，同时**严禁与主界面会话流中的 `A` 键归档冲突**。

## Decision

1. **快捷键分配与交互流转**：
   - 选定物理快捷键 `G` 作为会话详情界面的呼出/收起快捷键（`Q` 为浏览器保留键被排除；`G` 位于主行未占用，敲击顺手）。
   - 在快捷消息面板开启（`isQuickMsgOpen === true`）时：
     - `J` / `K` / `↓` / `↑`：上下移动光标选择快捷消息。
     - `Enter`：选中当前项**填入输入框**并展开 Composer，以便用户根据当前上下文微调修改后再回车发送。
     - `D`：一键删除当前选中的快捷消息，并同步更新持久化缓存。
     - `A`：快速新增快捷消息，呼出单行新增输入框；面板处于打开态时严格拦截主界面的 `A` 键会话归档，绝不误触发归档。
     - 面板底部采用纯文字提示条 `G 开关 · JK/触控板选择 · 回车填入对话框 · A 新增 · D 删除`，不放置额外的新增按钮，最大化 720x720 屏幕纵向空间。
     - `Esc` / 右上角 `✕` / 再次按 `G`：关闭面板。
2. **快捷消息持久化与默认模板**：
   - 使用 `localStorage` 键 `dsh_q20_quick_msgs` 持久化用户快捷消息列表。
   - 首次加载时预置实用指令（如“继续”、“请检查并修复错误”、“请给出下一步计划”、“精简回答”等）。
   - 兼顾 ES5 约束与 BB10 WebKit 537 渲染性能，列表采用经典 `.tree-panel` 与 `.tree-node` 风格，光标移动与选中完全贴合其他面板（`C`/`W`/`M`/`U`）的交互直觉。
3. **新增流程与防冲突状态机**：
   - 新增消息弹层激活时（`isQuickMsgInputOpen === true`），焦点切入单行输入框，物理键盘正常打字，所有字母全局快捷键（包含 `A`、`Q`、`J`、`K` 等）通过 `activeElement` input 守卫自动放行给原生输入；按 `Enter` 确认保存，按 `Esc` 或点击取消按钮收起。

## Alternatives considered

- **使用 `S` 或 `Q` 作为呼出键**：被否决。`S` 与 `Q` 均为 BlackBerry 10 浏览器内核保留快捷键（如速记/系统操作等），在旧 WebKit 下会被截获或产生心智冲突；改用主行未占用按键 `G`，全局无冲突。
- **选中后立即发送**：被否决。移动端常用消息往往需要微调上下文参数，直接发送容易误发未编辑内容；填入对话框并聚焦由用户确认后再发送更安全且符合心智。
- **使用原生 `window.prompt()` 新增**：被否决。老旧 BB10 WebKit 的 `prompt()` 对话框会阻塞事件循环且在某些系统版本下 UI 渲染不协调；采用统一的 Q20 暗色拟物悬浮小窗更为可靠。

## Consequences

- 丰富了 Q20 物理键盘的高频操作能力，常用指令一键发送，无需重复打字。
- 保证了 ES5 语法与 720x720 方屏无缝兼容，严格通过自动化测试与代码门禁。
