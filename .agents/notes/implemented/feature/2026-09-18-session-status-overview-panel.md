# Agent Note: 实体快捷键呼出当前会话全量状态概览面板

Status: implemented

## Problem

在黑莓 BlackBerry Q20 紧凑正方形屏幕（720×720）上，为了最大化对话流的阅读视野，界面顶栏高度被严格压缩在 32px 以内，且底栏对话框默认处于收起状态。虽然用户可以通过快捷键切换工作区（`W`）、浏览会话列表（`C`）、选择模型（`M`）和配置权限（`P`），但缺乏一个能够随时全局检视“当前会话全景体检报告”的直观入口。

特别是在执行长任务或多轮排查时，用户需要即时获知：
1. 当前会话的工作区归属与真实会话摘要（对齐 DSH Web 侧边栏的摘要呈现口径）；
2. 会话生命周期的真实运行状态（进行中/完成/用户终止/错误，带语义图标与高对比度色彩）；
3. 运行环境配置：权限等级、Agent 模式（Preset）；
4. 模型执行指标：当前模型（`provider/model` 样式）、已执行的对话轮次与 Agent 执行步数；
5. Token 消耗与吞吐表现：Token 生成速度（tok/s）、输入 Token、输出 Token 以及 Prompt 缓存命中率（Cache Hit Rate）。

## Decision

在前端与服务端联动实现全屏会话状态概览面板（Session Status Overview Panel），由实体物理快捷键 `O`（Overview）单键呼出与收起：

1. **服务端提供高内聚会话度量端点 (`/api/session/stats`)**：
   - 接收 `cwd` 与 `id`（会话 ID）；
   - 从会话底层 `jsonl.zstd` 转录日志中增量/缓存解析元数据与全量事件；
   - 提取 `session` 头中的 `agentPreset`（模式）与标题摘要；
   - 聚合统计 `turn/start`（轮次）与 `step/start` / `step/end`（步数）；
   - 统计每个 Assistant 步骤的 `usage`（`inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`），计算真实缓存命中率；
   - 结合步骤起止时间计算整会话平均或当前推理的 Token 吞吐速度（`tok/s`）；
   - 提取最近一次实际生效的模型调用（`provider/model`）；
   - 采用文件 mtime 与 size 的短 TTL 缓存策略，杜绝大转录文件频繁解压对双核 CPU 的压力。

2. **前端实现小方屏适配的状态概览模态窗 (`#status-overlay`)**：
   - 严格遵守 ES5 语法规范与经典 HEX 色彩体系（无 CSS 变量、无 Grid、无 flex 现代属性）；
   - 绑定物理快捷键 `O`（Key code: 79，非编辑态触发）用于一键展开/收起，并纳入关闭栈与帮助速查表；
   - 严格尊重黑莓 Q20 硬件事实：底栏提示绝不出现“按 Esc 关闭”误导文案，统一标明“O 键开关 · 触控右上角 ✕ 关闭”；
   - 极简结构重组：去除单独冗余的“会话状态”行，将字段名统一简称为“会话”，通过标题前的前置语义图标与高对比度色彩（蓝点进行中、绿勾完成、橙块终止、红叉错误）一体化直显会话状态与标题；
   - 会话标题提取对齐 DSH Web 规范：优先采用会话持久化标题，缺失时平滑回退至首轮提问或会话 ID 缩写；
   - 优化同步频率与视觉降噪：已完成的会话仅在面板打开及手动点击刷新时拉取一次度量，杜绝无意义的高频轮询和底部反复闪现的“正在同步”横条；仅在会话处于 active 运行态时才以舒缓的 6 秒间隔同步；
   - Token 统计采用更符合移动小屏阅读习惯的单位转换：去除冗余的“总计”行，所有数字自动格式化为 `K` 与 `M` 单位（如 `851.2K`、`1.20M`），并清晰标示未缓存、读缓存与缓存命中率。

3. **快捷键系统与文档闭环**：
   - 更新 `static/index.html` 中的快捷键速查面板（Help modal），登记 `O` 键功能；
   - 更新中英文项目文档中的黑莓 Q20 物理快捷键对照清单。

## Alternatives considered

- **方案 A：在顶栏常驻展示 Token 与状态卡片**：由于 Q20 屏幕仅 720×720，在阅读模式下顶栏若堆叠多行信息会导致视口严重被挤压，背离了方屏空间利用率与极简阅读原则。
- **方案 B：快捷键采用 `S`（Status）**：此前实践表明，在 BlackBerry 10 WebKit 537 浏览器内核下，按键 `S` 在部分固件版本中会被系统浏览器快捷键（如保存书签或查找）强行拦截，导致呼出失效；因此选用右上侧拇指可达且无浏览器系统级冲突的 `O`（Overview，Key code 79）。
- **方案 C：纯前端自行遍历历史消息计算 Token**：历史消息列表通过分页懒加载，前端内存中通常只驻留最新的 20 条消息，若强行在前端拉取完整历史会诱发低内存设备 OOM；交由服务端在 Node.js 端流式/单次解压统计并将轻量结果 JSON 返回，既准确又彻底保护了手机端低配置硬件。
- **方案 D：高频轮询已完成会话以维持度量实时性**：静态历史会话的转录与 Token 在终态后固定不变，固定周期轮询除了给低功耗芯片造成不必要开销并引发界面抖动外毫无增益，因此调整为按需加载与按运行态智能定频。
