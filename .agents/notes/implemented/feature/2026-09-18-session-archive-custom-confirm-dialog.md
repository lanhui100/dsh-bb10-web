# Agent Note: session-archive-custom-confirm-dialog

Status: implemented

## Problem

在 BlackBerry Q20 客户端执行会话归档操作（点击归档按钮或按下物理快捷键 `A`）时，当前实现调用了浏览器原生的 `window.confirm()` 对话框。该原生组件存在以下问题：
1. 视觉风格与 Q20 全局高对比度暗色主题（#121212 / #1E1E1E / #00897B）割裂，白底或系统样式极为突兀；
2. 弹出位置与层级脱离页面掌控，破坏沉浸式全屏方屏阅读；
3. 原生确认框依赖触摸或系统焦点操作，对 Q20 物理键盘（Enter 确认、X/Esc 取消）支持不友好。

## Decision

移除 `window.confirm` 原生调用，改为原生纯 CSS 与 ES5 实现的 Q20 定制确认弹窗：
1. **视觉与位置布局**：
   - 使用绝对定位半透明遮罩蒙层（`background: rgba(0,0,0,0.85); z-index: 400`）；
   - 弹窗本体采用居中偏上（`top: 24%` 或黄金阅读分割线，水平居中）紧凑卡片，宽度适配 720×720 方屏；
   - 采用统一高对比度暗色配色（背景 `#1E1E1E`，边框 `#333333`，操作按钮 `#00897B` 确定 / `#333333` 取消），展示当前会话标题与 ID。
2. **键盘与交互闭环**：
   - 弹窗打开时捕获键盘事件；
   - `Enter` 键执行确认归档；
   - `X` 键或 `Esc` 键（或点击取消按钮 / 右上角关闭按钮 / 遮罩）执行取消；
   - 状态隔离：弹窗激活期间拦截底层会话列表和消息流快捷键，避免快捷键击穿；
   - 弹窗关闭时自动归还焦点，并在状态栏给出提示。

## Alternatives considered

1. **沿用 `window.confirm()`**：开发零成本，但样式突兀、白底破坏暗色适配、且在部分 BB10 WebKit 版本上容易阻断主线程或出现焦点陷阱。
2. **复用 `question-panel` 全屏组件**：`question-panel` 为多步骤问答设计的全屏沉浸组件，用于简单的两态二选一确认过于沉重，缺乏“居中偏上轻量弹窗”的即时视觉感知。
3. **底部操作抽屉（ActionSheet）**：底部在 Q20 上靠近物理键盘边缘，对于重要归档确认容易误触，居中偏上的黄金视觉区更安全、视野更直接。
