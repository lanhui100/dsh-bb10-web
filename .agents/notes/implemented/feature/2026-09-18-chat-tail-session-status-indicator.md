# Agent Note: 消息流尾部添加会话状态指示组件并复用全局状态机

Status: implemented

## Problem

在用户进入会话（包括从会话面板切换到正在运行中的会话或历史已完成/中断的会话）时，最新消息下方缺少直观表达当前会话状态的视觉组件。

1. **官方 dsh web 的对齐参考**：
   - 官方 `dsh web`（`packages/client/ui-chat/src/client/chat/ChatView.tsx`）在所有消息节点的最底部挂载了 `TurnStatus` 组件（如显示 `深度求索中...` 结合流光动画，并在长轮次展示计时），实时表达会话正在进行中的语义；在非进行中或不同状态下也明确给出沉浸式反馈。
2. **当前 dsh-q20-web 的现状与缺陷**：
   - 前端已拥有标准且完备的会话全局状态机 `sessState`（`running`、`phase` 包含 `idle` / `running` / `stopped` / `done` / `error`、`lastError` 等）；
   - 但在消息滚动容器（`chatContainer`）的消息尾部，没有任何常驻的状态胶囊/指示卡片。
   - 当用户从会话面板进入运行中会话或历史会话时，最新消息下方直接是空白，用户无法在阅读流的最尾端明确获知：当前会话是处于“思考生成中”、“已完成”、“用户已手动停止”还是“异常中断”。

## Decision

1. **复用现有全局会话状态机 `sessState`**：
   - 不引入新的状态源，统一由 `sessState.phase` 与 `sessState.running` 驱动底部的状态指示器；
   - 任何触发 `sessState` 变化的链路（`attachSession` 的 `start`/`sync`/`thought`/`tool`/`delta`/`done`/`cancelled`/`error`、`startChatStream` 的实时推送、用户点击停止按钮、切换会话等）自动调用状态指示器的更新函数 `renderSessionStatusTail()`。
2. **在消息流最底部设计紧凑的高对比度状态胶囊组件 (`#sess-status-tail`)**：
   - **进行中（running）**：显示呼吸脉冲点与动态提示文字 `● 思考与生成中…`（高对比亮蓝/青色），提示用户会话正在执行；
   - **已手动中止（stopped）**：显示 `■ 会话已中止`（橙色 `#D96B27`）；
   - **完成（done）**：当有对话消息时显示紧凑的 `✓ 对话已完成`（高对比薄荷绿 `#4EC9B0`，背景 `#1A1A1A`），让用户在滑到底部时清楚知道本轮对话已闭环；
   - **错误（error）**：显示 `✖ 会话发生错误`（红色 `#F85149`），附带简短错误描述；
   - **空闲/新建（idle）**：当没有消息（空白欢迎页）或空白会话时不显示，不破坏全屏沉浸感。
3. **严格遵守黑莓 Q20 硬件与 ES5 规范**：
   - 采用经典 CSS（无 CSS 变量，纯 HEX 高对比度颜色）；
   - 呼吸动画使用双前缀 `@-webkit-keyframes` 与 `@keyframes`，性能开销极低；
   - 纯原生 DOM 操作，与 `chatContainer` 滚动高度数学联动，不干扰自动滚动（`scrollBottom`）与历史消息分页窗口。

## Alternatives considered

- **做成类似官方的文本背景流光动画（Shimmer）**：
  - *否决原因*：流光动画依赖 `-webkit-background-clip: text` 与线性渐变，老旧 WebKit 537.35 对此支持极差且在弱双核 CPU 上会引发严重的局部重绘掉帧，改用轻量平滑的透明度呼吸（pulse）与静态高对比度胶囊更加稳定耐用。
- **将状态只显示在顶部或只保留在按钮上**：
  - *否决原因*：用户阅读消息流的视线终点自然落在最新一条消息的下方，尾部指示器符合人机工程学，消除了用户对“是否还在输出/是否卡住”的疑惑。

## Consequences

- 用户无论进入正在运行的会话，还是浏览已结束、已中止的会话，都能在最新消息下方清晰感知到当前会话的客观运行时态；
- 状态机完全复用，与发送/停止按钮、会话面板中的状态标记保持 100% 同构一致。
