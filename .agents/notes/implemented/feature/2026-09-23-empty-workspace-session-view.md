# Agent Note: 空白工作区无会话独立状态视图展示

Status: implemented

## Problem
此前切换进入某个工作区时，如果该工作区尚无任何会话，系统直接自动弹出全屏会话列表抽屉（`openSess()`），或者直接展示全局居中新建对话欢迎页（探索未至之境），无法直观区分是“系统初始化就绪态”还是“当前选中的工作区暂无历史会话”，界面缺乏针对无会话工作区的独立空状态页面与明确指引。

## Decision
1. **新增独立无会话空状态页面结构与样式**：
   - 在 `chatContainer` 内新增 `#empty-workspace-view`（默认隐藏），包含大图标、动态工作区名称（如 `xxx 暂无会话`）以及开始新对话提示；
   - 样式遵循黑莓 720×720 方屏经典居中布局（`display: table / table-cell` 兼容老旧 WebKit，高对比度暗色主题），配备清晰的 `＋ 开始新对话 [I]` 交互触发按钮。
2. **工作区状态判断与联动渲染**：
   - 引入 `isCurrentWorkspaceEmpty()` 判断当前选中工作区的会话列表是否确实已加载且为空（`list.length === 0`）；
   - 在 `updateWelcomePlaceholder()` 中将全局初始化欢迎页与工作区独立无会话视图分流：当工作区无会话时，独立展示无会话状态视图，隐藏初始化欢迎语；
   - `selectWorkspace(cwd)` 切换进入工作区时：若缓存已知无会话，直接展示无会话页面并不再弹出会话列表面板；若未加载缓存，异步加载并在确认无会话时渲染该无会话页面；若已有会话则正常保持列表供用户选择。
3. **严格兼容红线**：
   - 客户端保持 100% 严格 ES5 语法，通过 Acorn 静态门禁与解耦契约门禁。

## Alternatives considered
- **保持弹出会话列表抽屉并在列表中显示“(暂无历史会话)”**：当工作区为空时弹出列表增加了多余的操作步骤，用户不得不手动按 X/Esc 收起列表才能进入主屏；直接在主工作区展示独立空状态视图更直观。
- **复用全局初始化“探索未至之境”欢迎语**：无法直观展示当前工作区名称与“该工作区暂无会话”的明确状态提示，易产生系统未进入工作区的歧义。
