# Agent Note: 优化历史记录加载与会话归档的 UIUX 与内存防崩溃体验

Status: implemented

## Problem

在 BlackBerry Q20 (BB10 WebKit 537.35+) 设备上（720x720 方屏，2GB RAM，骁龙双核 CPU），当前系统存在两处明显的 UI/UX 与性能问题：
1. **加载历史记录缺乏前置 loading 反馈与后端分页机制**：
   - 切换历史会话或初始化加载历史时，`loadHistory` 仅仅先清空容器 `chatContainer.innerHTML = ''` 并设置底部小字状态，在 XHR 响应返回前聊天视口呈现为空白，缺乏明确的加载中（loading）指示，用户无法感知是在加载还是无内容；
   - 接口 `/api/history` 默认将底层整个 zstd 解压并解析出的全部历史消息一次性返回（对于长对话可能有几十上百条消息包含庞大参数与输出），不仅浪费网络传输与 JSON 解析时间，而且在内存仅 2GB、老旧 WebKit 极其脆弱的设备上极易引起内存暴涨或页面卡死；
   - 缺乏懒加载（按需向前加载更早历史消息）的端到端支持。
2. **会话归档缺乏过程态 loading 交互**：
   - 用户在归档弹窗点击“📦 归档当前会话”或按快捷键 `A` 确认后，发起 `/api/session/archive` 请求期间，归档按钮没有禁用和 loading 状态提示（仍显示普通按钮状态），用户若多次点击可能触发重复请求，且无法直观得知系统正在归档中。

## Decision

对服务端 `server.mjs` 与客户端 `static/index.html` 进行如下优化，严格遵循 ES5 与经典 CSS 规范：

1. **历史记录加载前呈现视觉 loading 状态**：
   - 在进入 `loadHistory(cwd, id)` 时，在 `chatContainer` 中注入居中高对比度的加载指示卡片（如 `⏳ 正在读取历史消息...`，带轻量呼吸/点阵动画或醒目样式），并在状态栏同步显示加载状态；
   - 当请求返回成功并渲染消息后，loading 状态被自然替换；若请求失败，给出醒目的重试按钮或明确的错误卡片与状态提示。

2. **后端历史记录支持懒加载限制，前端按需拉取最新一定数量的消息**：
   - 服务端 `/api/history` 接口增加支持可选的 `limit` 和 `before` 查询参数（如 `limit=20`，默认不传或传 limit 时进行高效切片）：
     - 当指定 `limit` 时，默认返回最新的 `limit` 条消息，并提供 `total`、`hasMore` 等元信息或保持兼容格式，确保 test-suite 现有断言 100% 兼容；
     - 当用户在前端点击 `[⬆ 加载更早历史]` 时，通过 API 懒加载更早的一批消息，或前端分批加载最新消息，严格限制初次和增量常驻内存与 DOM 树节点数（单次默认 20 条，增量 10 条）；
     - 保持现有 `/api/history` 数组返回契约兼容，支持兼容返回数组或保留现有测试套件直接消费数组的能力。为了对测试套件及旧调用者 100% 保持向后兼容：当不传参数时仍返回完整数组；当传入 `limit` 参数时返回最新 `limit` 条记录（或支持向更早滚动拉取）。同时前端 `loadHistory` 优先指定拉取最新的 20 条，并在需要时按需拉取更早历史。

3. **会话归档过程添加 loading 状态与防重复点击锁定**：
   - 当触发归档操作时，将归档按钮文案切换为 `⏳ 归档中...`，设置 `disabled = true`，置灰并降低透明度；
   - 同步在状态栏和界面呈现明确的归档进行中反馈；
   - 在 XHR 终态（无论成功还是失败）统一恢复归档按钮的原始文案 `📦 归档当前会话` 与可点击状态，防止重复请求。

## Alternatives considered

1. **仅在前端进行 DOM 截断（保持服务端传输全部数据）**：
   - 前端已有的 `renderWindowedMessages` 虽然限制了当前 DOM 中可见的气泡数为 20，但在历史很长时，前端仍然接收并解析了数百条历史的大 JSON，这在 Q20 移动网络与 2GB 内存下依然存在较重解析开销。
   - 因此结合服务端 `limit` 懒加载与前端加载指示器是彻底根治长会话内存与渲染性能的最优解。
2. **引入现代通用 Spinners / CSS3 复杂动画库**：
   - 违背 BB10 WebKit 537.35+ 客观事实与性能准则，复杂 CSS 动画在老旧骁龙双核上会导致 CPU 满载甚至浏览器崩溃。选用经典高对比度纯文字/ASCII/Emoji 指示器最为稳定可靠。

## Consequences

- 满足用户在历史加载与会话归档全过程中的即时视觉反馈，彻底消除“操作无响应”的疑虑。
- 历史消息默认只加载最新的 20 条并支持向前分页追溯，大幅缩减初始传输体积与内存开销。
- 保持 ES5 纯前端代码语法，通过静态门禁与自动化全套回归套件。
