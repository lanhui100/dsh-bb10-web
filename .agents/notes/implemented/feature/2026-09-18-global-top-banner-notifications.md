# Agent Note: 全局顶部横幅通知组件与 E/D 快捷键联动

Status: implemented

## Problem

在黑莓 Q20 小屏环境下，会话在后台或前台执行完毕或出错时缺乏全局通知。用户在切会话或等待长任务时，无法实时察觉完成或错误状态。同时：
1. 原拟定快捷键 `H` 与帮助速查冲突，而 `G` 键为 BlackBerry 10 内核原生浏览器默认保留键（Go to URL），不可占用；需分配完全无冲突且手感连贯的快捷键；
2. 用户主动停止（按 `X` 停止、停止按钮、Esc 打断）在某些异步竞态或后端 abort 场景下可能抛出网络或流异常，必须保证主动停止的会话绝不误发错误横幅通知。

## Decision

在 `static/index.html` 中完善全局顶部横幅通知组件（`#top-banner-container`）：

1. **触发契机与主动停止/当前视口守卫**：
   - 监听会话完成与错误终态（`done` 与 `error`），严格排除运行态（`running`）及人工中止态（`stopped` / `cancelled`）；
   - 当前会话直面免打扰：若当前已处于该会话的消息流主界面（且无全屏 Overlay 弹窗遮盖），用户已在此界面直观目睹生成结束或错误反馈，直接抑制横幅通知，避免不必要地占用顶部高度；
   - 增加全局 `userStoppedSessions` 时间戳索引与关键字守卫（包含 cancel/abort/停止/中止/interrupted），确保主动停止绝不误触发错误横幅；
   - 覆盖前台流式（`/api/chat/stream`）、长连 Attach（`/api/session/attach`）以及多会话后台状态轮询对比。
2. **呈现与折叠**：
   - 图标 + 摘要形式（`✓` 绿色代表成功，`✖` 红色代表错误）；
   - 增量显示，默认最多显示 3 条；超出 3 条时自动折叠其余部分，提供折叠展开/收起栏；
   - 顶部通知栏与 `#chat-container.style.top` 数学联动下推避让，不遮挡消息流（宪法 §三.1）。
3. **交互与双键联动**：
   - 绝不自动消失，常驻直到用户处理；
   - 快捷键 `E`（keyCode 69，Enter）：直达并打开顶部首条通知会话，自动关闭各级弹窗并加载目标会话；
   - 快捷键 `D`（keyCode 68，Dismiss）：一键关闭顶部首条通知；
   - `E` 键位于 Q20 全键盘 `D` 键正上方，垂直成对盲打极其舒适，且完全避开浏览器原生保留键（`G` 为地址栏、`S` 为搜索、`H` 为历史）。

## Alternatives considered

- **使用 `G` 键作为直达首条横幅快捷键（已否决）**：`G` 键在 BB10 WebKit 浏览器内核中为跳转地址栏（Go to URL）默认保留键，直接占用会被系统截获或引起行为混乱。选用紧邻 `D` 键上方的 `E`（Enter）无冲突且操作连贯。
- **保留 `H` 键作为关闭通知快捷键（已否决）**：因 `H` 为黑莓 Q20 全局帮助速查保留快捷键，共用会导致热键冲突或心智混淆。选用主键区盲打友好的 `D`（Dismiss）更直观且无冲突。
- **仅依赖后端 status 区分取消**：如果网络层断开或 Harnees abort 较快，后端返回的可能为 socket error 或 0 字节断流，前端增加 `userStoppedSessions` 软锁是彻底杜绝误报的最佳方案。

## Consequences

- 异步会话的完成与异常能够全局感知，支持键盘 `E` 直达、`D` 消除或触控交互；
- 主动停止会话 100% 免疫错误横幅误报；
- 门禁合规：通过 Acorn ES5 静态解析、全量测试套件（7/7）与 `verify-note.sh` 验证。
