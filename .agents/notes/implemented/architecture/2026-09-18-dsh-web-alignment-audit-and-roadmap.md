# Agent Note: 宪法对齐 DSH Web 核心逻辑全维度审计报告与整改路线

Status: implemented

## Decision

根据项目宪法新确立的《业务与核心逻辑对齐准则（DSH Web 对齐原则）》，由多专家子代理从“数据模型与 Transcript 解析层”、“RPC 通信与宿主协议层”、“前端状态机与对话生命周期层”三大维度完成全面审计，并确立以下整改原则与改进清单：

1. **核心审计结论**：
   - 基础会话状态机同构（5 态：`idle` / `running` / `stopped` / `done` / `error`）、单一状态源驱动、双模工作区同步（RPC 优先 + 本地原子落盘兜底）对齐良好；
   - 存在 2 处违背宪法“不应自己实现一套单独逻辑”的严重偏差：
     1. 通信层：`/api/chat` 未接入官方流式通道，而是自制“每 100ms 轮询磁盘 Zstd 文件重组 SSE”；
     2. 路径/寻址层：未实现官方标准 `projectKey(cwd)` 算法，退化为全局目录遍历；
   - 存在 3 处由于过度精简导致的协议与健壮性偏差：
     1. 历史读取全量解压而非基于 Frame 逆向游标分页；
     2. 前端缺失 `pendingInteraction`（等待用户交互）状态感知；
     3. 停止（Stop）操作缺少禁用防连击过渡态。

2. **后续整改路线图（Action Items）**：
   - **P1 - 修复流式信道与 RPC 通信**：废除 `/api/chat` 磁盘轮询逻辑，全面对齐官方宿主流式管道或基于 Frame 追加通知；
   - **P2 - 对齐工作区寻址算法**：实现官方 `projectKey(cwd)` 编码规范，消除多工作区场景下的全量目录扫描；
   - **P3 - 历史消息流式游标逆向加载**：基于已有的 `scanZstdFrames` 逆向解析最近 20 条，杜绝超大 Transcript 触发全量解压；
   - **P4 - 前端状态完备性补全**：补齐 `pendingInteraction` 状态指示及 Stop 按钮点击后过渡置灰保护。

## Alternatives considered

1. **维持当前各模块私有自造逻辑**：长期维护容易随着 DSH 官方版本升级而产生协议腐烂与严重数据不一致，违背对齐宪法，否决。
2. **完全复制 DSH Web 前端源码**：受制于 ES5 纯语法与老旧 WebKit 537.35 限制，无法在 Q20 运行，必须在展示层坚持 ES5 / 经典 CSS / DOM 节流的硬件适配，而在协议与状态机层 100% 对齐官方。

## Consequences

- 本审计结论与改进路线图作为后续版本迭代的权威基线；
- 宪法对齐准则具备了可执行、可度量的量化检视清单。
