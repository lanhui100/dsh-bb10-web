# Agent Note: 多智能体面板团队任务与智能体一同完整显示

Status: implemented

## Problem

在用户通过物理按键 `U` 唤起多智能体与后台任务看板时，存在两处展示缺陷：
1. **工作区回退防串台检查误清空任务板**：当用户处于未独立派生子会话的主会话时，系统触发工作区兜底 `loadWorkspaceSubagentsFallback`，但若工作区内已有团队任务处于 `completed` 或 `pending` 状态且无正在执行的活跃 agent，旧检查逻辑会将 `data.tasks` 和 `data.subagents` 强行清空，导致任务板在所有任务完成后误报“工作区暂无”；
2. **零成员时的多余分组头**：当只有团队任务而无任何子智能体/teammate（如轻量级任务编排或任务刚初始化）时，面板下方仍渲染空白的“👥 团队与子智能体成员 (0)”分组头，造成界面冗余。

## Decision

1. **保留团队任务与智能体数据**：
   在 `loadWorkspaceSubagentsFallback` 中调整判定，唯有当无活跃运行项且 `wsTasks.length === 0 && wsSubs.length === 0` 时才清空数据，确保团队任务（无论已完成、进行中或等待中）和子智能体始终能够完整一同呈现。
2. **智能成员分组头渲染**：
   在 `renderSubagentTree()` 中增加 `list && list.length > 0` 防护，仅在实际存在子智能体/teammate 列表时渲染成员分组头，避免零成员时出现无意义的空横幅。
3. **保持 ES5 严苛兼容与测试闭环**：
   所有逻辑严守 ES5 标准，通过 Acorn 静态语法门禁以及单元与端到端测试。

## Alternatives considered

- 方案 A：在当前会话直接混入跨工作区的所有团队任务。
  - 否决：会彻底破坏多工作区与多项目之间的团队隔离边界。
- 方案 B：仅当有 `in_progress` 任务时才展示任务板。
  - 否决：用户需要随时查看已完成（completed）的任务概览与验收详情，强行隐藏已完成任务破坏了团队任务看板的连续性。

## Consequences

- 按 `U` 键后，团队任务与子智能体/teammate 能够在面板中一同稳定显示，不再因状态变动而误清空。
- 界面更紧凑干净，零成员场景下不再显示冗余空头。
- Acorn ES5 静态门禁与单元测试全部 100% 通过。
