# Agent Note: 严格会话级子智能体与团队任务隔离

Status: implemented

## Problem

在用户通过物理按键 `U` 唤起多智能体与团队任务面板时，存在跨会话污染与串台展示问题：
1. **客户端空会话触发工作区回退**：当当前会话暂无子智能体或团队任务时，客户端通过 `loadWorkspaceSubagentsFallback` 触发了工作区级回退，拉取了工作区乃至其他历史会话的子智能体和团队任务，导致在当前会话中误看到了其他会话的任务与智能体；
2. **服务端工作区聚合跨越全局**：服务端 `getWorkspaceSubagents` 在无活跃子智能体时尝试从全量宿主会话中兜底提取活跃项，越过了当前 `targetCwd` 与父子会话的隔离边界。

## Decision

1. **废弃客户端跨会话回退拉取**：
   在 `static/index.html` 的 `loadSubagents` 中，移除对 `loadWorkspaceSubagentsFallback` 的调用；当当前会话无子智能体或团队任务时，忠实展示当前会话空态，严格恪守会话作用域隔离边界。
2. **阻断跨工作区越界穿透**：
   在 `server.mjs` 中剔除无界限的跨工作区兜底注入，确保查询工作区时仅限当前工作区内的实体。
3. **测试门禁与 ES5 语法规范**：
   全量代码严格通过 Acorn `{ ecmaVersion: 5 }` 静态语法门禁以及全套回归测试。

## Alternatives considered

- 方案 A：在前端按时间戳只展示 5 分钟内的跨会话任务。
  - 否决：依然会发生串台，无法解决不同业务场景会话之间的任务隔离诉求。
- 方案 B：在面板中增加会话筛选下拉框。
  - 否决：720x720 小屏空间极小，增加控件违反极简与键盘第一原则。

## Consequences

- 按 `U` 键后严格仅展示当前会话自身拥有的团队任务和子智能体，彻底消除其他会话的串台污染。
- 全量门禁（Acorn ES5、test-unit 35/35、test-suite 7/7）100% 通过。
