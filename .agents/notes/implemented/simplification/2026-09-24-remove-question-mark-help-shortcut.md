# Agent Note: 去除 ? 快捷键呼出仅保留 H 呼出快捷键帮助

Status: implemented

## Problem

在 BlackBerry Q20 实体全键盘上，输入英文问号 `?` 需要通过组合按键（`Shift` + 物理键或字符表组合），且在部分键盘状态和输入流转中容易与常规文本输入或斜杠 `/`（展开输入框快捷键）产生按键冲突；同时快捷键速查面板既支持 `?` 又支持 `H`，存在冗余的按键映射。用户期望统一收敛快捷键帮助速查的唤起方式，去除 `?` 触发，仅保留单键 `H` 呼出。

## Decision

1. **移除 `?` 快捷键监听**：在 `static/index.html` 的全局 `keydown` 监听器中，移除 `code === 63` 与 `code === 191 && isShift`（`?` / `Shift+/`）的呼出判定，仅保留非修饰键按下时的 `H`（`code === 72`）单键切换帮助速查面板。
2. **界面与文案对齐**：
   - 更新 `#help-overlay` 快捷键速查表格中对应行的按键显示，从 `? 或 H` 统一为 `H`；
   - 更新欢迎页快捷键卡片（`#welcome-ready`）提示由 `? : 快捷键帮助` 调整为 `H : 快捷键帮助`；
   - 同步更新根目录中英文 `README.md` 与 `README.zh.md` 的快捷键列表说明。

## Alternatives considered

- **保留 `?` 仅在 PC 桌面端生效**：增加判断客户端运行环境（如 UA 或屏幕尺寸）决定是否启用 `?`。
  - *未采纳原因*：增加了客户端状态分支与维护成本，单键 `H`（Help）记忆成本低且全平台行为统一确定，无需保留冗余多键映射。

## Consequences

- 快捷键速查入口收敛为单键 `H`，消除了与打字输入及复合键触发潜在的按键冲突。
- 欢迎页与帮助面板提示文案一致。
