# Agent Note: 测试分级架构与专用沙箱工作区物理隔离

Status: implemented

> 部分取代（2026-09-30）：本条的"第二层保留至少一套真实端到端"已被
> `2026-09-30-real-link-tests-to-mock-and-q20rm-cleanup.md` 取代（真链路改 mock）；
> 第一层单元分级与沙箱隔离思路继续有效。

## Problem

原测试套件（`test-suite.mjs`）在默认测试流程中直接在开发者日常工作区（如仓库根目录及相邻工作区）创建真实大模型会话：
1. **真实会话侵入日常工作区**：即使后续有严格归档逻辑，测试过程中依然会触碰宿主 DSH Web 的全局注册表，触发真实的 WebSocket/Feed 推送，造成界面短暂抖动与历史记录残留风险；
2. **测试成本高且存在脆弱外部依赖**：7 大测试场景全部依赖线上模型推理与外网网络，易因上游 TPM/RPM 限流（429）或网络波动导致误报失败，且每次全量耗时约 40 秒，不适合作为高频提交的默认门禁；
3. **职责混杂**：历史 Zstd 解压、HTTP 参数边界校验、空输入拦截等逻辑本质上属于纯本地无副作用的单元逻辑，完全不需要真实调用外部大模型。

## Decision

1. **短期：端到端测试强制隔离至专用测试沙箱工作区**：
   在 `test-suite.mjs` 中不再使用任何开发者日常工作区。测试启动时自动创建临时沙箱目录（如 `/tmp/q20-test-sandbox-<timestamp>`），所有端到端真实会话均在沙箱工作区内创建；测试结束后无论成功还是异常，均在 `finally` 阶段对沙箱工作区及内部会话进行归档清理与目录回收，彻底杜绝污染开发者的日常工作区。
2. **长期：测试分级架构（Tiered Testing）**：
   - **第一层：本地单元/契约测试（`test-unit.mjs`）**：
     将历史 Zstd 解压还原（使用固定无害的测试夹具 Fixture）、API 参数 400 校验、无效会话防御、会话状态机推断等无副作用逻辑独立为轻量单元测试套件。零网络开销、零 Token 消耗、零会话产生，毫秒级完成，作为默认轻量回归门禁。
   - **第二层：端到端真机验收测试（`test-suite.mjs`）**：
     专注于验证 Q20 服务端与宿主 DSH Web RPC、SSE 事件流协议与打字机节流机制的真实连通性。默认在沙箱中运行核心链路；支持 `--live` 参数执行完整多模型全链路回归。
3. **更新宪法与验收门禁（DoD）**：
   门禁第二道关卡明确分级：常规高频验证运行 `node test-unit.mjs`；集成回归运行 `node test-suite.mjs`（沙箱隔离）。

## Alternatives considered

- **维持单一体并在主工作区边测边删**：落选。一旦测试过程中断或网络断开，垃圾仍会残留在工作区视图中，无法做到根本物理隔离。
- **完全废除真实模型调用、仅保留 Mock**：落选。本项目是深度依赖 DSH 宿主 RPC 与真实 WebKit 流式分发协议的伴侣服务，必须保留至少一套沙箱隔离下的真实端到端连通性测试，以保障发布前的绝对可靠性。

## Consequences

- 开发者主工作区与 DSH Web 侧边栏获得 100% 物理层面的测试隔离保护；
- 日常回归测试可在毫秒级完成，大幅提升开发迭代速度并降低对上游模型配额的依赖。
